## Partnership source audit

Reviewed 2026-11-17 against Postiz commit `36d5fc7b3ac3f17178b1589cf7a7337523017a41`.

- The pinned README mentions exchanging or buying posts. The complete Git tree returned by GitHub was untruncated. The frontend retains a marketplace illustration, and the audited route inventory contains no marketplace, listing, offer or order controller. [Pinned tree](https://github.com/gitroomhq/postiz-app/tree/36d5fc7b3ac3f17178b1589cf7a7337523017a41)
- The Prisma schema retains buyer and seller records, messages, order items with a channel, quantity and price, payout problem records and links to posts. Its order states are pending, accepted, canceled and completed. These establish a historical data model. The audit did not establish who can create or accept an offer, how placement review works, or what triggers fulfillment. [Pinned Prisma schema](https://github.com/gitroomhq/postiz-app/blob/36d5fc7b3ac3f17178b1589cf7a7337523017a41/libraries/nestjs-libraries/src/database/prisma/schema.prisma)
- The generic payment webhook delegates to the registered provider layer. RevenueCat is the only implementation in that directory. The pinned environment example still lists a Stripe Connect signing key. Current self-hosting documentation lists that variable and the fee setting as removed and documents Stripe separately for subscriptions. [Pinned payment providers](https://github.com/gitroomhq/postiz-app/tree/36d5fc7b3ac3f17178b1589cf7a7337523017a41/libraries/nestjs-libraries/src/services/payment/providers), [Current configuration reference](https://github.com/gitroomhq/postiz-docs/blob/main/self-host/configuration/reference.mdx)
- The public documentation index has no marketplace entry. To establish a live workflow, obtain authenticated access for both sides and observe listing, offer, review, confirmation of publication and, for paid placements, test checkout through settlement or refund. [Postiz documentation index](https://docs.postiz.com/llms.txt)
